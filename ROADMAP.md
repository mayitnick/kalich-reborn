## 🔴 Фаза 1: Критические исправления (P0 - Блокеры сборки и деплоя)

Цель: гарантировать корректную сборку и запуск всех сервисов в локальной среде и в Docker.

- [x] **1.1. Исправление зависимостей бэкенда (`requirements.txt`)**
  - Добавить `aiohttp` в `requirements.txt` (требуется для `api_server.py`).
  - Зафиксировать минимальные рабочие версии зависимостей.
  - Удалены неиспользуемые тяжелые библиотеки (`gtts`, `pydub`, `Pillow`, `audioop-lts`).

- [x] **1.2. Исправление `Dockerfile.frontend`**
  - Удалить несуществующую стадию сборки Node.js (`npm ci` / `package.json`), так как PWA использует чистый HTML/JS/CSS.
  - Настроить образ Nginx для прямого копирования статики из папки `pwa/` в `/usr/share/nginx/html`.

- [x] **1.3. Синхронизация портов и конфигурации `docker-compose.yml`**
  - Согласовать порты API: в `api_server.py` и `docker-compose.yml` (приведено к единому значению `8999`).
  - Настроить проброс тома с базой данных `data/` в `docker-compose.yml` для персистентности данных между перезапусками.

- [ ] **1.4. Устранение блокировок Event Loop в `api_server.py`**
  - Обернуть тяжелые синхронные вызовы (`kalich.fetch_lessons`, работу с SQLite, генерацию аналитики) в `await asyncio.to_thread(...)`, чтобы они не блокировали обработку параллельных HTTP-запросов.

## 🟠 Фаза 2: Архитектурный рефакторинг монолита (P1)

Цель: разделить почти 3900-строчный монолит `kalich.py` на независимые слои (Single Responsibility Principle).

- [x] **2.1. Создание модульной структуры проекта (`src/`)**
  - Организовать структуру пакетов:
    ```text
    src/
    ├── config/          # Конфигурация и переменные окружения (.env)
    ├── database/        # Модели, миграции и слой доступа к SQLite
    ├── services/
    │   ├── parser.py    # Парсинг сайта колледжа и дедупликация хешей
    │   ├── analytics.py # Генерация отчетов и диаграмм Matplotlib
    │   ├── audio.py     # TTS генерация (gTTS) и аудиоэффекты (pydub)
    │   └── notifier.py  # Утренние рассылки и уведомления о заменах
    ├── bot/
    │   ├── handlers/    # Обработчики команд, сообщений и callback-кнопок
    │   ├── keyboards/   # Инлайн и реплай клавиатуры
    │   └── bot_instance.py
    └── api/             # Aiohttp контроллеры и роутинг
    ```

- [ ] **2.2. Консолидация хранилищ данных в SQLite**
  - Перенести данные из разрозненных JSON-файлов (`data/active_monitors.json`, `data/custom_names.json`, `data/groups_cache.json`) в таблицы SQLite.
  - Исключить потенциальные race conditions при параллельной записи в JSON.

- [ ] **2.3. Слой доступа к данным (Database Layer)**
  - Реализовать единый контекстный менеджер / класс для безопасного управления соединениями и транзакциями с SQLite.

## 🟡 Фаза 3: Безопасность и стабильность (P2)

Цель: защитить API от злоупотреблений и предотвратить сбои под нагрузкой.

- [ ] **3.1. Усиление авторизации и валидации API**
  - Требовать валидную подпись `initData` Telegram WebApp для всех закрытых эндпоинтов (создание замен, настройки, действия преподавателей).
  - Исключить возможность подделки `chat_id` / `device_id` в открытых запросах.
  - Добавить валидацию входных данных (через схемы/типизацию).

- [x] **3.2. Настройка SQLite для многопоточной работы**
  - Включить режим `PRAGMA journal_mode=WAL;` (Write-Ahead Logging) для бесконфликтного чтения при одновременной записи.
  - Настроить `PRAGMA busy_timeout = 5000;`.

- [ ] **3.3. Внедрение Rate Limiting**
  - Добавить ограничение частоты запросов к API и к парсеру сайта колледжа для защиты от перегрузки.

- [ ] **3.4. Очистка обработки ошибок и логирование**
  - Заменить «тихие» перехваты исключений (`except Exception: pass` / `except BaseException: pass`) на логирование ошибок с контекстом (`logger.exception`).
