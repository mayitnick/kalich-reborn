# Kalich 🦊

[![CI](https://github.com/mayitnick/kalich-reborn/actions/workflows/python-app.yml/badge.svg)](https://github.com/mayitnick/kalich-reborn/actions/workflows/python-app.yml)

![Database](https://img.shields.io/badge/SQLite-WAL%20Mode-success)
![Framework](https://img.shields.io/badge/API-aiohttp-orange)

**Kalich** — современная информационная платформа для студентов и преподавателей колледжа: многофункциональный Telegram-бот и высокопроизводительный REST API сервер. Система обеспечивает динамический парсинг расписания, отслеживание замен в реальном времени, управление кабинетами преподавателей и глубокую аналитику учебной нагрузки.

---

## ✨ Ключевые возможности

### 📅 Динамическое расписание (Глорис)
- **Парсинг без хардкода**: автоматический сбор актуального списка групп со всех 3-х отделений колледжа (`глорис-окту-1.рф`, `глорис-окту-2.рф`, `глорис-окту-3.рф`).
- **Умный поиск на лету (`find_group_info`)**: бот понимает нестрогие форматы ввода («ис 21 25», «ИС-21-25», «ис2125») и автоматически делает запрос к сайту, если группа была создана недавно.
- **Многоуровневое кэширование**: дедупликация изменений по MD5-хешам и сохранение истории по датам.
- **Фоновое обновление**: ежечасная фоновая синхронизация списка групп в `data/groups_cache.json`.

### 🔔 Уведомления и замены
- **Мгновенные оповещения**: при изменении расписания в колледже бот рассылает точечные уведомления подписанным студентам.
- **Утренние рассылки**: автоматическая рассылка расписания на текущий день с учётом всех подтверждённых замен.
- **Определение совмещений**: выявление пар, проходящих в одном кабинете одновременно.

### 🧑‍🏫 Панель преподавателя
- **Привязка кабинетов**: автоматический сбор расписания конкретного преподавателя по списку его кабинетов.
- **Быстрые переносы и замены (`/move`)**: смена предмета или аудитории прямо из чата с отложенным оповещением студентов (~5 минут на отмену).
- **Система верификации**: регистрация преподавателей с подтверждением модератором (`/start` → выбор роли).

### 📊 Аналитика и инфографика
- **Распределение предметов**: круговая диаграмма нагрузки по предметам (`/stats`).
- **Распределение по дням недели**: столбчатая диаграмма занятости.
- **Анализ кабинетов**: выявление наиболее загруженных аудиторий.
- Генерация аккуратных изображений диаграмм через `matplotlib` без блокировки основного потока.

### ⚡ Производительность и стабильность
- **SQLite WAL Mode**: включен режим Write-Ahead Logging (`PRAGMA journal_mode=WAL;` и `busy_timeout=5000`) для параллельной работы бота и REST API без блокировок базы данных.
- **Облегченная архитектура**: удалены тяжелые мультимедиа-библиотеки для мгновенного запуска и минимального потребления памяти.
- **Health Check**: эндпоинт `/api/health` для мониторинга статуса базы данных и парсера.

## 🤖 Команды Telegram-бота

### 🎓 Для студентов
| Команда | Описание |
|---------|----------|
| `/r` | Расписание на сегодня для своей группы |
| `/db [день/дата]` | Расписание на конкретный день (`/db вт`) или дату (`/db 16.09.2026`) |
| `/w [группа]` | Быстрый просмотр расписания любой группы колледжа на сегодня |
| `/now` | Информация о текущей паре и прогресс-бар оставшегося времени |
| `/next` | Информация о следующей паре и времени до её начала |
| `/time` | Звонки и таймер до конца текущей пары или перемени |
| `/stats` | Графическая аналитика учебной нагрузки группы |
| `/unsub` | Отписаться от группы или сбросить профиль |
| `/cancel` | Отмена текущего многошагового действия (выбор группы/отделения) |
| `/settings` | Настройки уведомлений и персонального режима |

### 🧑‍🏫 Для преподавателей
| Команда | Описание |
|---------|----------|
| `/r` | Личное расписание на сегодня по всем привязанным кабинетам |
| `/db [день]` | Личное расписание на выбранный день недели |
| `/move [день] [пара] [кабинет] [п=Предмет] [группа]` | Замена кабинета или предмета (с задержкой 5 мин на отмену) |
| `/cancel_move [id]` | Отмена созданной замены аудитории/предмета |
| `/list` | Просмотр своего преподавательского статуса и кабинетов |

### 🛡️ Для администраторов и модераторов
| Команда | Описание |
|---------|----------|
| `/flush` | Очистка кэша текущей недели из базы данных |
| `/fill` | Массовое предзаполнение базы расписанием на неделю для всех отделений |

## 🚀 Быстрый старт

### Требования
- Python 3.10+
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)

### 1. Клонирование репозитория

```bash
git clone https://github.com/mayitnick/kalich-reborn.git
cd kalich-reborn
```

### 2. Создание виртуального окружения

```bash
python3 -m venv venv
# Linux / macOS:
source venv/bin/activate
# Windows:
venv\Scripts\activate

pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Настройка окружения (`.env`)

Создайте файл `.env` на основе примера:

```bash
cp .env.example .env
```

Заполните ключевые переменные:
```env
BOT_TOKEN=123456789:ABCdefGHIjklMNOprstUVWXYZ       # Токен бота
MODERATOR_ID=123456789                              # Telegram ID администратора
LOG_GROUP_ID=-1001234567890                         # (Опционально) ID группы для пересылки сообщений
PWA_PORT=8000                                       # Порт REST API сервера
```

### 4. Запуск

**Запуск Telegram-бота:**
```bash
python3 kalich.py
```

**Запуск REST API сервера:**
```bash
python3 api_server.py
# Сервер запустится на http://localhost:8000
```

> **Примечание**: При первом запуске каталог `data/` и файл базы данных `data/schedules.db` будут созданы автоматически с оптимизированными настройками WAL.

## 🐳 Запуск через Docker

В репозитории подготовлена Docker-конфигурация для запуска бэкенда и API:

- Персистентные данные базы и кэша сохраняются в томе `./data:/app/data`.

## 🔌 REST API Reference

Базовый URL: `http://localhost:8000`

### Состояние и мониторинг
| Метод | Эндпоинт | Параметры | Описание |
|-------|----------|-----------|----------|
| `GET` | `/api/health` | — | Проверка здоровья API, соединения с SQLite и количества спарсенных групп |

### Расписание и группы
| Метод | Эндпоинт | Параметры | Описание |
|-------|----------|-----------|----------|
| `GET` | `/api/groups` | `?refresh=true` (опц.) | Список всех спарсенных учебных групп по отделениям |
| `GET` | `/api/schedule` | `department`, `group_id`, `day` или `date` | Расписание группы на день или дату |
| `GET` | `/api/teacher/schedule` | `chat_id`, `day` | Расписание преподавателя по кабинетам |

### Пользователи и авторизация
| Метод | Эндпоинт | Тело запроса | Описание |
|-------|----------|--------------|----------|
| `POST` | `/api/auth` | `{"device_id": "..."}` | Авторизация клиента / устройства |
| `POST` | `/api/auth/request_teacher` | `{"chat_id": ..., "name": "...", "department": 1, "rooms": "101,102"}` | Подача заявки на статус преподавателя |
| `POST` | `/api/settings` | `{"chat_id": ..., "notifications": 1}` | Сохранение настроек пользователя |

### Управление заменами и аналитика
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `POST` | `/api/override` | Создание или изменение замены преподавателем |
| `POST` | `/api/sync` | Пакетная синхронизация локальных замен |
| `GET` | `/api/analytics` | Получение агрегированных данных нагрузки |
| `GET` | `/api/admin/overrides` | Список всех активных замен (для администраторов) |
| `POST` | `/api/admin/delete_override` | Удаление замены |
| `POST` | `/api/admin/fill` | Фоновое предзаполнение базы расписанием |
| `POST` | `/api/admin/flush` | Очистка кэша расписания |

## 🧪 Тестирование и CI/CD

Проект сопровождается набором unit-тестов с изолированной базой данных и мокированием сетевых запросов:

```bash
# Запуск всех тестов
pytest tests/

# Запуск тестов с отчетом о покрытии
PYTHONPATH=. pytest tests/ --cov=.

# Проверка линтером flake8 (согласно правилам GitHub Actions)
flake8 . --count --select=E9,F63,F7,F82 --show-source --statistics
```

В проекте настроен автоматический пайплайн **GitHub Actions** (`.github/workflows/python-app.yml`), выполняющий линтинг и прогон тестов при каждом пуше и PR.

## 🔧 Технологический стек

- **Бот**: [pyTelegramBotAPI (telebot)](https://github.com/eternnoir/pyTelegramBotAPI)
- **API**: [aiohttp](https://docs.aiohttp.org/)
- **База данных**: SQLite3 (WAL Mode + busy_timeout)
- **Парсинг**: BeautifulSoup4 + requests
- **Визуализация**: matplotlib (Agg backend)
- **Тестирование**: pytest, pytest-cov, pytest-mock
- **CI/CD**: GitHub Actions
- **Контейнеризация**: Docker, Docker Compose
